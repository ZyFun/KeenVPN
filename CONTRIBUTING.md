# Участие в разработке KeenVPN

KeenVPN содержит утилиты диагностики Python и офлайн-аудита пакетов Entware. Изменения должны быть небольшими и проверяемыми.

## Перед началом работы

1. Проверьте существующие Issues, чтобы не создавать дубликат.
2. Для ошибки заполните форму Bug report, для новой возможности — Feature request.
3. Не публикуйте уязвимости и секреты в Issues. Используйте [приватное сообщение об уязвимости](https://github.com/ZyFun/KeenVPN/security/advisories/new).
4. Согласуйте крупное изменение до реализации.

## Ветки разработки

- `dev` — основная ветка разработки. Ветки задач создаются от актуальной `dev`, результаты задач возвращаются в неё через Pull Request.
- `main` — только стабильное состояние, готовое к выпуску. Подготовленные и проверенные изменения переносятся из `dev` в `main` при подготовке релиза; повседневная разработка в `main` не ведётся.
- Перед созданием ветки проверьте рабочее дерево и не переносите в неё незавершённые изменения другой работы.

## Pull Request

- Для обычной задачи выбирайте базовую ветку `dev`. PR из `dev` в `main` предназначен для подготовки стабильного выпуска.
- Ограничьте PR одной связной задачей.
- Объясните, что изменено и зачем.
- Добавьте или обновите тесты при изменении поведения.
- Обновите документацию, если изменился пользовательский сценарий.
- Укажите риски, способ отката и фактически выполненные проверки.
- Не утверждайте, что изменение проверено на роутере, если выполнялись только локальные тесты.

## Локальная проверка Python

Используйте CPython 3.12 или новее и [перечень необходимых модулей](docs/python-runtime.md). Из корня проекта:

```sh
python3 -I -S -B scripts/check_python.py
python3 -I -S -B -m unittest discover -s tests -v
```

Эти команды не требуют роутера. Проверка аппаратной среды, установка пакетов и запуск на действующем Keenetic требуют отдельного разрешения и не подменяются локальными тестами.

Для проверки локального индекса и IPK используйте отдельный [офлайн-аудит Entware](docs/entware-runtime.md). Обычный набор тестов не скачивает эти пакеты и использует искусственные архивы и открытый тестовый CA.

## Документация

Описывайте только реализованное поведение: существующие команды, входные данные, вывод, ограничения и способы проверки. Сверяйте утверждения с кодом и тестами.

Не добавляйте дорожные карты, обещания новых возможностей, историю организации работ или разделы про несуществующие функции. Если полезного описания текущей реализации нет, не создавайте файл или раздел ради заполнения структуры. При удалении или переносе текста проверяйте связанные ссылки.

## Язык и оформление

Документация, пользовательские сообщения и описания изменений пишутся на русском языке. Python-идентификаторы и названия протоколов сохраняются в исходном виде.

Заголовок коммита пишется в инфинитиве без точки, например:

```text
Уточнить вывод диагностики Python
```

## Приватные данные

Перед отправкой проверьте diff. В репозиторий не должны попадать VPN URI, пароли, токены, закрытые ключи, личные IP-адреса, MAC-адреса и рабочие конфигурации без обезличивания.
