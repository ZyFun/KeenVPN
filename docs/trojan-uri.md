# Разбор Trojan URI

Функция `keenvpn.adapters.trojan_uri.parse_trojan_uri(uri)` преобразует строку подключения Trojan с TLS и WebSocket в `TrojanConnection`. Она работает только в памяти: не выполняет DNS-запросы, не соединяется с сервером, не запускает команды и не читает или записывает файлы.

## Использование

Модуль находится в каталоге `keenvpn` исходного дерева. Для импорта корень репозитория должен быть в пути поиска Python. Нужен CPython 3.12 или новее; сторонние библиотеки не используются.

Пример вызова из Python с закрытым вводом:

```python
from getpass import getpass

from keenvpn.adapters.trojan_uri import TrojanURIError, parse_trojan_uri

try:
    connection = parse_trojan_uri(getpass("Ссылка подключения: "))
except TrojanURIError as error:
    print(error.code.value, str(error))
else:
    print(connection)  # Параметры скрыты.
```

Это API Python, а не отдельная команда для настройки VPN. Не передавайте ссылку в аргументах shell-команд и не сохраняйте её в истории терминала.

## Вход и результат

Принимается одна строка длиной до 16 384 символов со схемой `trojan`, паролем перед `@`, адресом и явным портом из одной–пяти ASCII-цифр. IPv6-адрес заключается в квадратные скобки. Завершающий `/` после порта допустим; путь WebSocket берётся только из параметра `path`.

| Вход | Поле модели | Поведение |
|---|---|---|
| Адрес и порт | `server`, `port` | Адрес без скобок IPv6 и целочисленный порт |
| Пароль перед `@` | `password` | Объект `SecretValue` с маскированным выводом |
| `security=tls` | `security` | Обязательный режим TLS |
| `type=ws` | `transport` | Обязательный транспорт WebSocket |
| `sni` | `sni` | Строка или `None`, если параметр отсутствует |
| `host` | `host` | Строка или `None`; не подменяется адресом сервера |
| `path` | `path` | Строка; при отсутствии — `/` |
| `fp` | `fingerprint` | Строка или `None` |
| Часть после `#` | `name` | Строка или `None`, если фрагмент отсутствует |

Параметры query, пароль и имя декодируются один раз из percent-encoding как UTF-8. Символ `+` остаётся плюсом. Пустое переданное значение отличается от отсутствующего. Адрес сервера не преобразуется через IDNA и не декодируется из percent-encoding.

Неизвестные query-параметры и другой протокол, режим безопасности или транспорт отклоняются. Параметры не теряются молча. Дубликаты, отсутствующий адрес/пароль/порт, порт вне диапазона 1–65535, нарушенные escape-последовательности, недопустимый UTF-8 и управляющие ASCII-символы приводят к ошибке. Неэкранированные пробельные символы во входной строке также отклоняются, а не удаляются.

### Обязательные поля и проверка параметров

- Нужны непустые пароль и адрес, явный порт, `security=tls` и `type=ws`. Режим безопасности и транспорт не определяются автоматически. Отсутствующие или пустые `security`/`type` — ошибка `invalid_uri`; другое непустое значение — `unsupported_uri`.
- Порт не декодируется из percent-encoding. Допустимы 1–5 ASCII-цифр и итоговое число 1–65535: `00001` означает порт 1, а `0`, `65536`, `000443`, `+443` и цифры других алфавитов отклоняются.
- Имена query-параметров и значения `tls`/`ws` чувствительны к регистру. Схема `trojan` принимается в любом регистре. Ключи и значения сравниваются после одного percent-декодирования.
- Каждый из `security`, `type`, `sni`, `host`, `path`, `fp` разрешён только один раз. Дубли отклоняются и при одинаковых, и при противоречивых значениях, независимо от их порядка. Первый или последний экземпляр не выбирается автоматически.
- Каждая query-пара должна иметь непустое имя и разделитель `=`. Пустые пары между `&&`, в начале или конце query недопустимы. Неизвестные параметры отклоняются даже с пустым значением, включая опции отключения проверки TLS.

Поля `sni`, `host`, `path`, `fp` и имя подключения необязательны; их пустые переданные значения сохраняются. Проверки обязательности не добавляют значения по умолчанию к этим полям, кроме `/` при отсутствующем `path`.

### Декодирование значений

Сначала выделяются части ссылки и пары query, затем каждое значение декодируется отдельно. Поэтому `%40` внутри пароля не становится разделителем адреса, а `%26` и `%3D` внутри пути не создают дополнительные параметры подключения.

| Переданное значение | Результат декодирования |
|---|---|
| `A+%2B%20B` | `A++ B` |
| `%2Fsocket%3Fx%3D1%26y%3D2` | `/socket?x=1&y=2` |
| `%252Fsocket` | `%2Fsocket`, без повторного декодирования |
| `%66%69%72%65%66%6f%78` | `firefox` |
| `Cafe%CC%81` | `Cafe` и комбинируемый акцент, без преобразования в другую форму Unicode |

Пароль, path, SNI, Host, fingerprint и имя проходят одно и то же декодирование. Регистр текста не меняется, пробелы, переданные через `%20`, не обрезаются. Декодирование SNI/Host не включает IDNA-преобразование. Пустой query-параметр или пустой фрагмент остаётся пустой строкой, а не заменяется значением по умолчанию.

Имена query-параметров также декодируются один раз до проверки допустимости и дублей: `sni` и `%73ni` обозначают один ключ. Полученный при декодировании символ `%` не запускает второй проход.

Исходная Python-строка должна быть представима в UTF-8: суррогатные кодовые точки U+D800–U+DFFF отклоняются, в том числе записанные парой. Корректные Unicode-символы и emoji принимаются. Ошибочные UTF-8-последовательности в percent-encoding отклоняются без подстановки символа замены. Управляющие ASCII-символы после декодирования также запрещены.

## Ошибки и приватные данные

`TrojanURIError` содержит безопасный русский текст и код:

| Код | Значение |
|---|---|
| `invalid_uri` | Неверный тип, размер или синтаксис входа |
| `unsupported_uri` | Неподдержанный формат или набор параметров |

В `error.reason` возвращается дополнительная причина (`TrojanURIErrorReason`) или `None` для общей ошибки формата/декодирования. Для программной обработки используйте `code`/`reason`, а не сравнение русского текста сообщения.

| Причина | Значение |
|---|---|
| `invalid_endpoint` | Неверная структура адреса и порта или некорректный IPv6 |
| `invalid_port` | Пустой порт, недопустимая запись или число вне диапазона |
| `missing_password` | Пустой пароль перед `@` |
| `missing_security`, `missing_transport` | Отсутствующий или пустой обязательный режим безопасности / транспорт |
| `invalid_query` | Неверная структура пары query |
| `duplicate_parameter` | Повтор известного query-параметра после декодирования имени |
| `unsupported_scheme`, `unsupported_security`, `unsupported_transport` | Неподдержанная схема, режим безопасности или транспорт |
| `unsupported_parameter` | Неизвестное имя query-параметра |

Парсер останавливается на первой обнаруженной ошибке; это не список всех проблем ссылки. Повреждение структуры адреса может быть обнаружено раньше проверки порта. Причина и сообщение содержат только фиксированные значения, без исходной ссылки, пользовательского имени параметра или его значения.

Ожидаемая ошибка выходит из `parse_trojan_uri` новым экземпляром: сохраняются `code` и `reason`, но не низкоуровневое исключение декодера/IPv6, его контекст и внутренние кадры разбора. В собственном кадре публичной функции входная строка удалена перед отказом. Это действует и при вызове парсера внутри внешнего `except`; чужая ошибка не изменяется и не добавляется в цепочку отказа.

Сам парсер ничего не печатает и не пишет в журнал. `str()`/`repr()` всей модели скрывают параметры, в том числе произвольный текст имени или пути. `str()` и `repr()` пароля также маскированы; для доступа к строке нужен явный `connection.password.reveal()`. Стандартное текстовое логирование модели и неизменённой ошибки не подставляет значения их приватных полей.

### Безопасная диагностика

Для журналов и JSON-отчётов используйте отдельные представления:

```python
import json

report = connection.to_diagnostic()
print(json.dumps(report, ensure_ascii=False))
```

`connection.to_diagnostic()` возвращает новый словарь с фиксированными ключами:

| Ключи | Содержимое |
|---|---|
| `protocol`, `security`, `transport` | `trojan`, `tls`, `ws` |
| `parameters` | Маркер `<скрыто>` |
| `has_sni`, `has_host`, `has_fingerprint`, `has_name` | `True`, если поле присутствует, в том числе пустое; `False`, если оно равно `None` |

Адрес, порт, пароль, SNI, Host, путь, fingerprint и имя не копируются в отчёт. Длины и хеши значений также не включаются. Произвольное поле может содержать пароль или целую ссылку, поэтому диагностика не пытается угадать, какая его часть является секретной. Исходная модель не изменяется.

`error.to_diagnostic()` возвращает только `code` и `reason` как строки; отсутствующая причина представлена `None` (`null` в JSON). В словарь не попадают `args`, заметки, дополнительные атрибуты, traceback и контекст исключения. Сообщение пользователю можно получить через `str(error)` до добавления в ошибку произвольных данных внешним кодом.

Модель — приватные данные, а не диагностический отчёт. `dataclasses.asdict(connection)` сохраняет произвольные значения полей, хотя пароль остаётся объектом `SecretValue`: такой словарь нельзя отправлять в журнал или публичный отчёт. Используйте `to_diagnostic()`, а не универсальную сериализацию объектов.

Эта защита не очищает кадры вызывающего кода, строки исходников в traceback, дампы памяти или вручную раскрытые поля. Не выводите исходную ссылку, `reveal()` и локальные переменные всего стека. Не добавляйте секреты в сообщения, заметки и дополнительные атрибуты исключений. `SecretValue` уменьшает риск случайного вывода, но не шифрует пароль в памяти.

## Границы проверки

Успешный разбор подтверждает только описанный синтаксис. Он не проверяет существование домена, доступность сервера, TLS-сертификат, допустимость конкретных SNI/Host/пути/fingerprint для Xray или работу VPN. Поля модели доступны для чтения, но их нельзя присвоить заново.
