# Сессия черновика

Модуль `keenvpn.domain.draft_session` описывает одну редактируемую сессию черновика изменений: идентификатор, время создания и [исходные отпечатки](#исходные-отпечатки) управляемых источников в строгом версионированном формате. Он разбирает и собирает байты файла в памяти и ничего не читает с диска. Адаптер `keenvpn.adapters.draft_session_files.DraftSessionFiles` хранит файл сессии в явно заданном собственном каталоге; порт `DraftSessionStore` и его отказы определены в `keenvpn.application.ports`. Над портом работают [прикладные сценарии](#прикладные-сценарии) создания, просмотра, проверки актуальности и отмены.

Черновик ничего не применяет: адаптер и сценарии не меняют конфигурацию Xray и XKeen, настройки Keenetic и службы, не вызывают команды XKeen и не меняют роутер. Создание и проверка актуальности только читают отпечатки источников, их содержимое не разбирается. Файл сессии не размещается в каталогах конфигураций Xray и XKeen и каталоге init, поэтому Xray не может загрузить его как свою часть. В этой версии сессия не содержит изменений и состояния: наличие файла означает открытую сессию. Сборка меню принимает хранилище черновика только явно (`MenuSources(drafts=...)`), а режимы запуска `vpn-menu`, `vpn-menu --read-router` и `vpn-setup` его не подключают: каталог по умолчанию не выбран. Пункты раздела «Черновик и применение» недоступны. Подключённое хранилище читают область «Черновик» [сводки](status-summary.md) и [решение о выходе](cli-menu.md#выход-при-неприменённом-черновике) из меню; оба только читают файл.

## Формат

Файл — объект JSON версии схемы `1`:

```json
{
  "format": "keenvpn-draft-session",
  "schema_version": 1,
  "draft_id": "00000000-0000-4000-8000-0000000000d1",
  "created_at": "2026-11-01T02:14:16Z",
  "baseline": {
    "xray_configs": {"state": "present", "parts": {"01_log.json": "<SHA-256>", "02_dns.json": "<SHA-256>"}},
    "xkeen_settings": {"state": "present", "sha256": "<SHA-256>"},
    "xkeen_init": {"state": "absent"}
  }
}
```

В примере раздел `baseline` сокращён: созданный сценарием черновик содержит все источники перечня.

| Поле | Значение |
|---|---|
| `format` | Строка `keenvpn-draft-session`; без неё файл не считается черновиком, в том числе файл [метаданных менеджера](manager-metadata.md) |
| `schema_version` | Целое `1`; другая версия не угадывается и не мигрирует |
| `draft_id` | UUID `8-4-4-4-12` в нижнем регистре, выданный при создании; регистр не нормализуется |
| `created_at` | Момент создания в UTC с точностью до секунды: `YYYY-MM-DDTHH:MM:SSZ`, год из четырёх цифр; несуществующие дата и время отклоняются |
| `baseline` | Необязательный раздел [исходных отпечатков](#исходные-отпечатки); черновик без него остаётся допустимым файлом версии 1 |

Модель — `DraftSession(draft_id, created_at, extra, baseline=None)`: `created_at` — `datetime` с `tzinfo=timezone.utc` без долей секунды, `extra` — [`UnknownFields`](manager-metadata.md#неизвестные-поля), `baseline` — `SourceBaseline` либо `None`. Конструктор требует точных типов: подкласс `str` или `datetime`, наивное время и другой часовой пояс не проходят.

Поля, неизвестные этой версии формата, сохраняются на верхнем уровне так же, как в метаданных менеджера: каноническим JSON-снимком, после известных полей в исходном порядке; поле с именем известного задать нельзя. Будущие разделы формата добавляются как необязательные поля верхнего уровня.

## Строгое чтение и ревизия

`decode_draft_session(content)` принимает байты и возвращает `StoredDraftSession(session, revision)`. Отклоняются:

- не байты, не UTF-8 и файл больше `MAX_DRAFT_SIZE` (1 МиБ) — `invalid_draft_content`;
- комментарии, дубли ключей, `NaN`, `Infinity`, BOM, вложенность глубже 64 и не объект верхнего уровня — `invalid_draft_json`;
- неверный маркер формата, версия не целое положительное число, отсутствие `draft_id` или `created_at` — `invalid_draft_format`;
- другая версия схемы — `unsupported_draft_schema_version`, остальные поля не разбираются;
- `draft_id` и `created_at` неверного формата — `invalid_draft_id` и `invalid_draft_created_at`;
- раздел `baseline`, нарушающий [строгий разбор](#исходные-отпечатки), в том числе `null`, — `invalid_draft_baseline`.

Ревизия — SHA-256 байтов файла (`draft_revision`), как у метаданных менеджера. `encode_draft_session(session)` заново проверяет модель и возвращает ASCII-текст с отступом и переводом строки в конце; повторное кодирование прочитанного канонического файла даёт те же байты. `validate_draft_session(session)` пересобирает модель из её собственных полей и неизвестные поля из их снимка.

`DraftSessionError` содержит `code` (`DraftSessionErrorCode`) и `field` — имя поля формата либо `None`; значения и имена неизвестных полей в ошибку не попадают, чужое исключение в `__context__` не сохраняется. Коды: `invalid_draft_content`, `invalid_draft_json`, `invalid_draft_format`, `unsupported_draft_schema_version`, `invalid_draft_id`, `invalid_draft_created_at`, `invalid_unknown_fields`, `invalid_draft_baseline`, `invalid_draft_revision`, `invalid_draft_session`.

`DraftSession.to_diagnostic()` возвращает версию схемы, идентификатор, время создания строкой, число неизвестных полей и `baseline` — источники с состояниями либо `None`; `repr` показывает идентификатор, время, только число неизвестных полей и число источников, без хешей.

## Исходные отпечатки

При создании черновика сценарий фиксирует, в каком состоянии были источники, которыми управляет менеджер. Модуль `keenvpn.domain.source_baseline` описывает перечень источников, модель отпечатка и раздел `baseline`; порт `SourceFingerprintSource` определён в `keenvpn.application.ports`, его реализация на роутере — [`SourceFingerprints`](router-sources.md#исходные-отпечатки).

| Источник `BaselineSource` | Что фиксируется |
|---|---|
| `xray_configs` | Набор имён `*.json` каталога конфигураций Xray и SHA-256 байтов каждой части по порядку имён; служебные части входят наравне с остальными |
| `xkeen_settings` | SHA-256 байтов `xkeen.json` |
| `xkeen_init` | SHA-256 байтов стартового сценария XKeen |
| `xkeen_port_exclude`, `xkeen_port_proxying`, `xkeen_ip_exclude` | SHA-256 байтов каждого из трёх списков |
| `keenetic_policies` | SHA-256 канонического JSON всего ресурса RCI `ip/policy`, включая разрешённые подключения политик |
| `keenetic_hotspot_settings` | SHA-256 канонического JSON всего ресурса RCI `ip/hotspot` |

Геобазы, реестр регистраций `known/host`, наблюдаемое состояние клиентов `show/ip/hotspot` и процесс Xray не фиксируются. Порядок перечня — порядок чтения и записи.

Канонический JSON (`native_fingerprint`) — ключи объектов по порядку, массивы в исходном порядке, без пробелов, в ASCII. Перестановка ключей отпечаток не меняет, а перестановка разрешённых подключений, замена `true` на `1`, новое или удалённое поле — меняют. В ресурсах `ip/policy` и `ip/hotspot` нет счётчиков, поэтому значим весь объект, включая неизвестные менеджеру поля.

Отпечаток `SourceFingerprint(source, state, sha256=None, parts=None)` имеет состояние `present` или `absent`. Подтверждённое отсутствие файла, каталога или его родителя — `absent` без хешей; отсутствие, замеченное в каталоге, который во время чтения заменён по пути, — отказ чтения `changed`. Пустой файл — `present` с SHA-256 пустых байтов, пустой каталог частей — `present` с пустым набором `parts`. Новая, удалённая или переименованная часть Xray меняет набор. Источник, который прочитать не удалось, отпечатка не получает: порт передаёт отказ чтения, и черновик не создаётся.

Разбор раздела строгий (`parse_source_baseline`):

- у записи известного источника ровно поля своего состояния: `state` и `sha256`, у `xray_configs` — `state` и `parts`, у `absent` — только `state`;
- состояние — `present` или `absent`, другое значение отклоняется;
- SHA-256 — 64 шестнадцатеричные цифры в нижнем регистре;
- имя части — допустимое имя файла без каталога с окончанием `.json`, не скрытое, частей не больше 64;
- порядок ключей не значим: источники упорядочиваются по перечню, части — по имени.

Записи источников, неизвестных этой версии, сохраняются без изменений после известных: сравнить их эта версия не может, поэтому проверка актуальности такой черновик блокирует. Раздел может перечислять не все источники; сценарий создания всегда записывает все. Неизвестная запись, которую строгий разбор файла не прочитал бы из-за глубины вложенности, не записывается: `invalid_draft_baseline`.

Хеши и имена частей не попадают в `repr`, диагностику, представления сценариев и ошибки: по хешу файла с малой изменчивостью можно проверить догадку о его содержимом. `SourceBaseline.to_diagnostic()` возвращает источники с состояниями и число неизвестных записей. `rebuild_source_baseline(baseline)` и `validate_source_fingerprint(fingerprint)` заново проверяют готовые модели из точных типов. `same_fingerprint(first, second)` сравнивает два отпечатка: тот же источник, то же состояние и те же хеши, у каталога частей Xray — тот же набор имён; `absent` совпадает только с `absent`. Сравнение с текущим состоянием источников выполняет [проверка актуальности](#прикладные-сценарии).

`SourceBaselineError` содержит `code`: `invalid_baseline_source`, `invalid_baseline_state`, `invalid_baseline_digest`, `invalid_baseline_parts`, `invalid_baseline_entry`, `invalid_source_baseline`, `invalid_native_document`. Хешей, имён частей и значений в ошибке нет; при разборе файла черновика любой из них даёт `invalid_draft_baseline`.

## Файловое хранилище

`DraftSessionFiles(directory, *, protected_directories=PROTECTED_DIRECTORIES)` реализует `DraftSessionStore`. Механика приватного файла общая с [хранилищем метаданных](manager-metadata.md#файловое-хранилище) — модуль `keenvpn.adapters.private_files`:

- `directory` — абсолютный нормализованный путь собственного каталога, например `/tmp/mnt/<UUID>/draft`. Значения по умолчанию нет. Каталог, совпадающий с `/opt/etc/xray`, `/opt/etc/xkeen` или `/opt/etc/init.d` либо вложенный в них, отклоняется до обращения к файловой системе.
- Ни один компонент пути не может быть символической ссылкой. Родитель каталога должен существовать: адаптер не создаёт родителей и не переключается на другой каталог, `/opt` или RAM. Идентичность раздела по UUID и свободное место заранее не проверяются.
- Каталог должен принадлежать текущему пользователю и иметь права `700`, файл `draft-session.json` — обычный файл владельца с правами `600`; права не исправляются.
- `read_draft()` возвращает `None`, если каталога или файла ещё нет, и не берёт блокировку.
- `create_draft(session)` сначала кодирует модель: некорректная вызывает `DraftSessionError` без обращения к файлам. Затем при необходимости создаёт каталог с правами `700`, берёт эксклюзивный неблокирующий `flock` каталога, удаляет временные файлы прерванной записи и требует, чтобы черновика не было: существующий, в том числе с теми же байтами, — `draft_revision_conflict` без перезаписи. Файл публикуется так же, как метаданные: временный файл с правами `600`, fsync, повторная проверка отсутствия черновика и неподменённого каталога, переименование и fsync каталога. Возвращается ревизия.
- `remove_draft(expected_revision)` проверяет формат ревизии (неверный — `DraftSessionError` без обращения к файлам), берёт ту же блокировку, открывает файл, сверяет ревизию, проверяет, что путь указывает на удерживаемый файл, удаляет его и выполняет fsync каталога. Отсутствующий черновик и другая ревизия — `draft_revision_conflict`; повреждённый файл не удаляется. Удаляется только файл сессии: собственный каталог и чужие файлы в нём остаются. Файл, появившийся после удаления до проверки, которая следует за fsync каталога, не трогается — `draft_revision_conflict`.
- `confirm_draft_absent()` закрепляет на диске отсутствие черновика, ничего не удаляя: берёт ту же блокировку, проверяет, что файла нет и каталог не подменён, выполняет fsync каталога и повторяет проверки. Нужен повтору отмены после `draft_write_unconfirmed`. Нет собственного каталога — подтверждать нечего, каталог не создаётся. Файл или другой объект по пути черновика, в том числе повреждённый или ссылка, — `draft_revision_conflict` без удаления; отказ fsync — снова `draft_write_unconfirmed`.
- Создание, удаление и подтверждение отсутствия через адаптер исключают друг друга блокировкой. Процесс, который меняет файл в обход блокировки, обнаруживается вплоть до последней проверки перед переименованием или удалением; изменение в промежутке между ней и самой операцией адаптер обнаружить не может: атомарного «сравнить и заменить» или «сравнить и удалить» в POSIX нет. Подмена каталога во время операции даёт `draft_store_unsafe` с причиной `replaced`.

Отказы — `DraftSessionStoreError` с полями `failure` (`DraftStoreFailure`) и `reason` (`StoreReason` или код домена) и фиксированным текстом без путей и системного сообщения:

| `failure` | Когда | `reason` |
|---|---|---|
| `draft_store_unavailable` | Родитель отсутствует, каталог или файл не читается | `missing`, `permission_denied`, `io_error`, `no_space`, `read_only` |
| `draft_store_unsafe` | Недопустимый или защищённый каталог, ссылка, не каталог или не обычный файл, чужой владелец, неверные права, подмена каталога или файла | `invalid_directory`, `protected_directory`, `symlink`, `not_directory`, `not_regular_file`, `owner`, `permissions`, `replaced` |
| `draft_store_busy` | Блокировку держит другая операция | — |
| `draft_revision_conflict` | При создании черновик уже есть; при удалении его нет или ревизия другая; при подтверждении отсутствия по пути черновика что-то есть | — |
| `invalid_stored_draft` | Файл нарушает формат или имеет другую версию схемы | код домена: `invalid_draft_json`, `unsupported_draft_schema_version` и другие |
| `draft_write_failed` | Не удалось создать каталог, записать, закрепить или переименовать временный файл либо удалить файл; прежнее состояние сохранено | `no_space`, `read_only`, `permission_denied`, `io_error` |
| `draft_write_unconfirmed` | Созданный файл виден или удалённый исчез, но fsync каталога не удался, в том числе при подтверждении отсутствия; состояние нужно перечитать | `io_error` |

`KeyboardInterrupt` и `SystemExit` проходят наружу; до переименования или удаления прежнее состояние файла не меняется, а временный файл удаляется. Процесс, убитый между записью и переименованием, оставляет только временный файл, который удаляет следующая операция.

## Прикладные сценарии

Модуль `keenvpn.application.draft_session` содержит четыре сценария над портом `DraftSessionStore`; решение о выходе из меню (`InspectMenuExit`) — в модуле `keenvpn.application.menu_exit` над тем же портом с общим [контрактом результата](application.md#результат); коды отказов и следующие шаги — в [описании прикладных сценариев](application.md#сессия-черновика).

- `InspectDraft` — `InspectDraftHandler(store)` один раз читает черновик. `data` — `DraftStatusView(present, draft)`; без черновика `present=False`, это состояние, а не отказ.
- `CreateDraft` — `CreateDraftHandler(store, fingerprints, *, draft_ids=new_draft_id, clock=utc_now)` один раз читает хранилище; существующий черновик — отказ `draft_exists` без чтения источников и без записи. Затем по одному разу читает отпечаток каждого источника перечня через порт `SourceFingerprintSource`. Первый недоступный источник останавливает чтение: отказ `draft_baseline_unavailable` с кодом отказа чтения в `reason`, файл не создаётся. Некорректный отпечаток или отпечаток другого источника — `invalid_draft_baseline_source`. Иначе создаёт сессию с новым UUID, временем `clock()` в UTC без долей секунды и разделом `baseline`; ревизия, которую вернуло хранилище, должна совпасть с SHA-256 канонических байтов, иначе — `invalid_draft_store_result`. `data` — `DraftView`.
- `DiscardDraft(draft_id=..., expected_revision=...)` — идентификатор и токен ревизии из `DraftView`; неверный формат любого из них — `invalid_command` без чтения хранилища. `DiscardDraftHandler(store)` один раз читает хранилище. Нет черновика — хранилище закрепляет его отсутствие (`confirm_draft_absent`), затем `DraftDiscardView(outcome="already_absent")`: повтор после `draft_write_unconfirmed` не сообщает успех, пока удаление не закреплено на диске, а отказ подтверждения возвращается как отказ хранилища. Другой идентификатор — отказ `draft_mismatch`, другой токен — `draft_revision_conflict`, оба без удаления; совпадающий удаляется по прочитанной ревизии — `outcome="discarded"`.
- `CheckDraftBaseline(draft_id=..., expected_revision=...)` — те же поля, что у отмены. `CheckDraftBaselineHandler(store, fingerprints)` проверяет, не устарел ли черновик, и ничего не записывает. Нет черновика, другой идентификатор или токен — те же конфликты черновика, что у отмены, источники при этом не читаются. Иначе сценарий по одному разу читает отпечаток каждого источника перечня, в том числе не зафиксированного в черновике, и сравнивает с исходным; отказ одного источника не останавливает чтение остальных. Затем черновик читается повторно: изменившийся или исчезнувший за время проверки — `draft_revision_conflict`. Изменившийся, исчезнувший или появившийся источник, источник без записи в черновике, черновик без раздела `baseline` или с неизвестными записями — отказ `draft_baseline_changed` с записью конфликта по каждому такому источнику и шагом «создать черновик заново». Источник, который прочитать не удалось, совпадением не считается: если других расхождений нет, отказ несёт код и причину первого отказа чтения. Успех — `DraftBaselineCheckView(outcome="current", draft_id)`. Ту же проверку выполняет общий помощник `check_draft_current`; при успехе он возвращает прочитанный черновик с ревизией из чтения. Проверка — снимок на момент чтения: изменение после её завершения она не обнаруживает.

`DraftView` содержит `draft_id`, `revision` — непрозрачный токен ревизии, `created_at` строкой, `unknown_field_count` и `baseline` — `DraftBaselineView` с источниками и их состояниями (`BaselineSourceView(source, state)`) и числом неизвестных записей либо `None`, если раздела в файле нет. Путь, ревизия файла, хеши, имена частей, имена и значения неизвестных полей в результаты не входят. Отказ создания или удаления, в том числе `draft_write_unconfirmed`, не превращается в успех.

Токен ревизии — первые 128 бит SHA-256 от метки домена и ревизии файла, 32 шестнадцатеричные цифры в нижнем регистре (`draft_revision_token`). Любое изменение байтов файла, в том числе внешняя правка, меняет токен, поэтому команда с токеном устаревшего представления отклоняется конфликтом и ничего не удаляет. Токен не совпадает ни с ревизией файла, ни с хешами источников и не позволяет их получить. Отказы `draft_exists`, `draft_mismatch` и `draft_revision_conflict` при создании, удалении и проверке актуальности несут [запись конфликта](application.md#конфликт-ревизий) черновика без токенов и ревизий.

## Пример

```python
import os
import tempfile

from keenvpn.adapters.draft_session_files import DraftSessionFiles
from keenvpn.adapters.router_sources import SourceFingerprints
from keenvpn.application.draft_session import (
    CheckDraftBaseline, CheckDraftBaselineHandler, CreateDraft, CreateDraftHandler, DiscardDraft, DiscardDraftHandler,
    InspectDraft, InspectDraftHandler,
)

store = DraftSessionFiles(os.path.realpath(tempfile.mkdtemp()) + "/draft")
# Пустой временный корень вместо роутера и подставной RCI: файлы источников отсутствуют.
root = os.path.realpath(tempfile.mkdtemp())
fingerprints = SourceFingerprints(root=root, read=lambda resource: {})
created = CreateDraftHandler(store, fingerprints).execute(CreateDraft())
discard = DiscardDraft(draft_id=created.data.draft_id, expected_revision=created.data.revision)
assert [item.state for item in created.data.baseline.sources] == ["absent"] * 6 + ["present"] * 2
assert CreateDraftHandler(store, fingerprints).execute(CreateDraft()).error.code == "draft_exists"
check = CheckDraftBaseline(draft_id=created.data.draft_id, expected_revision=created.data.revision)
assert CheckDraftBaselineHandler(store, fingerprints).execute(check).data.outcome == "current"
# Внешнее изменение: появился список исключений портов XKeen.
os.makedirs(root + "/opt/etc/xkeen")
open(root + "/opt/etc/xkeen/port_exclude.lst", "wb").close()
stale = CheckDraftBaselineHandler(store, fingerprints).execute(check).error
assert (stale.code, stale.next_step.code.value) == ("draft_baseline_changed", "recreate_draft")
assert [item.to_dict() for item in stale.conflicts] == [
    {"subject": "source", "source": "xkeen_port_exclude", "expected": "absent", "found": "present"},
]
assert InspectDraftHandler(store).execute(InspectDraft()).data.draft.revision == created.data.revision
stale = DiscardDraft(draft_id=created.data.draft_id, expected_revision="0" * 32)
assert DiscardDraftHandler(store).execute(stale).error.code == "draft_revision_conflict"
assert DiscardDraftHandler(store).execute(discard).data.outcome == "discarded"
assert DiscardDraftHandler(store).execute(discard).data.outcome == "already_absent"
print(InspectDraftHandler(store).execute(InspectDraft()).data.to_dict())
```

Пример читает и пишет только во временных каталогах, к роутеру и сети не обращается и печатает `{'present': False, 'draft': None}`.
