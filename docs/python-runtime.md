# Требования к Python

Статус: базовое требование первой версии и локальная диагностическая утилита. Это не установщик, не готовое меню и не подтверждение совместимости с реальным роутером.

## Минимальная версия

Базовая ветка — **CPython 3.12**. Код первой версии не должен требовать синтаксиса или API, появившихся только в 3.13 и новее. Нужен стабильный выпуск Python 3; PyPy, MicroPython, prerelease и будущий Python 4 не входят в эту границу.

Это выбранная граница сопровождения, а не утверждение, что сценарии невозможно написать на Python 3.11:

- У Python 3.12 запланирована поддержка безопасности до октября 2028 года, у 3.11 — до октября 2027 года, у 3.10 — до октября 2026 года. Для нового проекта выбираем более длинный срок сопровождения. [Статусы версий Python](https://devguide.python.org/versions/).
- В 3.12 доступны фильтры извлечения `tarfile`, включая `data_filter`. Их переносили и в исправления старых веток; поэтому наличие нужного API проверяется отдельно от номера версии. [Документация tarfile](https://docs.python.org/3.12/library/tarfile.html#extraction-filters).
- В просмотренном 9 сентября 2026 года официальном каталоге Entware `aarch64-k3.10` пакеты Python имеют версию `3.13.9-2`: выбранная нижняя граница не требует ветки новее опубликованной. Это наблюдение каталога, не рекомендация конкретного исправления и не аппаратная проверка. [Каталог Entware](https://bin.entware.net/aarch64-k3.10/Packages.html).

Запись «3.12» **не означает рекомендацию устанавливать 3.12.0**. Для эксплуатации нужна актуальная сборка с исправлениями безопасности в отдельно проверенной матрице Entware. Диагностическая утилита проверяет нижнюю границу и возможности, но не аудит уязвимостей и не допустимость автоматического обновления. Более новая минорная версия может пройти эту проверку, не становясь от этого проверенной платформой KeenVPN.

## Обязательные модули стандартной библиотеки

Это прямые требования планируемых сценариев первой версии. Транзитивные зависимости стандартной библиотеки не нужно перечислять вручную: их отсутствие также должно приводить к ошибке импорта. `sys` используется самой утилитой до остальных импортов.

| Область | Модули | Назначение и граница |
|---|---|---|
| Терминальный интерфейс | `argparse`, `getpass`, `termios`, `logging` | Аргументы, закрытый ввод и контролируемые сообщения; только во входном адаптере. При недоступном закрытом вводе нельзя незаметно печатать пароль |
| Модели и координация | `dataclasses`, `enum`, `typing`, `contextlib` | Типизированные данные, состояния, контракты портов и освобождение ресурсов |
| Форматы и адреса | `json`, `re`, `ipaddress`, `urllib.parse`, `base64`, `binascii` | JSON-метаданные, URI, IP/CIDR и кодирование; разбор URL не заменяет валидацию |
| Unicode и домены | `unicodedata`, `encodings.idna` | Нормализация текста и встроенный IDNA-кодек. Его наличие не обещает поддержку всех правил IDNA 2008 |
| Файлы и копии | `pathlib`, `os`, `stat`, `shutil`, `tempfile`, `io` | Пути, права, приватные временные файлы и атомарная замена через адаптер хранения |
| Ревизии и идентификаторы | `hashlib`, `hmac`, `secrets`, `uuid` | SHA-256, сравнение проверочных значений, случайные токены и ID. Хеш из недоверенного источника не доказывает подлинность релиза |
| Блокировки, процессы и время | `fcntl`, `subprocess`, `signal`, `errno`, `time`, `datetime` | Блокировка POSIX, запуск с аргументами списком и таймаутом, обработка ошибок и время операций |
| Сетевые адаптеры | `socket`, `ssl`, `urllib.request`, `urllib.error`, `http.client` | Ограниченные сетевые запросы и HTTPS. Стандартная библиотека не предоставляет SSH-клиент; наличие Python не подтверждает наличие внешнего SSH-транспорта |
| Архивы | `tarfile`, `gzip`, `zlib` | Чтение и формирование tar/gzip через отдельный адаптер. Фильтр извлечения задаётся явно; дополнительно нужны ограничения путей, типов файлов, размера и распаковки |

Указанные модули не дают разрешения смешивать CLI с доменной логикой или выполнять файловые/сетевые операции при импорте модулей менеджера. Проверка `flock` и файловых API здесь подтверждает только наличие интерфейсов: блокировку, атомарность, `fsync`, права и восстановление после сбоя на USB ещё нужно проверить отдельно. [fcntl](https://docs.python.org/3.12/library/fcntl.html), [os](https://docs.python.org/3.12/library/os.html).

### Что не является обязательной зависимостью

- `pip`, `setuptools`, `wheel`, `venv` и `ensurepip` не нужны для запуска этой утилиты. Способ упаковки будущего менеджера определяется отдельно.
- `sqlite3` не требуется: первая версия планирует JSON-метаданные, не новую серверную базу данных.
- `curses`, `asyncio`, `multiprocessing`, `ctypes`, `tomllib`, `zoneinfo`, `bz2`, `lzma` и `zipfile` сейчас не объявляются прямыми требованиями. Их необходимость определяется конкретным сценарием, а не наличием в полной установке Python.
- Нет обязательных сторонних Python-библиотек для этой задачи. Не добавляются Rich, Click, Paramiko, Requests, PyYAML, веб-фреймворк или Python-реализация VPN.
- Для локальных тестов разработчика дополнительно нужны `unittest`/`unittest.mock` и `importlib.util`. На роутере тестовый набор автоматически не устанавливается.

Это не перечень пакетов для `opkg install`. В Entware `python3-base` содержит лишь интерпретатор и минимум для запуска, `python3-light` — распространённые части библиотеки; например, `logging` выделен отдельно. [Исследование пакетов Entware, SSL/CA и места](entware-runtime.md) связывает эти требования с содержимым официальных IPK и отделяет статический аудит от аппаратной приёмки. Нельзя заключать, что все модули есть, только по успешному `python3 --version`.

## Диагностика Python

Из корня репозитория, на локальном компьютере с выбранным интерпретатором:

```sh
python3 -I -S -B scripts/check_python.py
```

`-I` изолирует запуск от пользовательского Python-окружения, `-S` отключает обработку `site` и установленных дополнений, `-B` запрещает запись `.pyc`. Проверяется выбранный исполняемый файл; утилита ничего не устанавливает и не ищет другой Python для успешного fallback. [Параметры запуска Python](https://docs.python.org/3.12/using/cmdline.html).

Утилита импортирует модули из таблицы и дополнительно проверяет наличие ключевых API, SHA-256, JSON/Unicode, IDNA, gzip в памяти и создание клиентского TLS-контекста с включённой проверкой имени и сертификата. Она не открывает сокеты, не запускает команды, не распаковывает архивы и не меняет конфиги.

При создании TLS-контекста намеренно не используется `create_default_context`: тот может открыть файл из `SSLKEYLOGFILE`. Проверка здесь не загружает хранилище CA и не выполняет handshake; реальному HTTPS-адаптеру всё равно понадобится проверенное хранилище доверенных сертификатов. [Документация ssl](https://docs.python.org/3.12/library/ssl.html#ssl.create_default_context).

| Код завершения | Значение |
|---|---|
| `0` | Пройден этот набор проверок версии, модулей и возможностей Python |
| `1` | Не подходит версия/реализация либо отсутствует/не работает обязательный модуль или API |
| `2` | Переданы аргументы, которых утилита не принимает |

Ошибки перечисляются по имени известной проверки без traceback, исходного текста исключения или повторения аргументов пользователя. При отказе по версии остальные модули не импортируются: это позволяет получить понятный ответ даже из старой или облегчённой среды. Утилита рассчитана на диагностику доверенного интерпретатора, не на безопасное исполнение посторонних модулей.

**Код `0` не подтверждает:** актуальность security-исправлений, установленный набор Entware, доверенные CA, работу HTTPS, файловые гарантии USB, модель/версию KeeneticOS, совместимость Xray/XKeen, DNS, Pritunl или маршрут через VPN. Перед переносом и запуском проверки на действующем роутере требуется отдельное разрешение; установка Python на нём не входит в этот шаг.

## Локальные тесты и границы проверки

Использовать CPython 3.12 или новее с указанными модулями:

```sh
python3 -I -S -B -m unittest discover -s tests -v
```

Проверяются граница версий, prerelease и другая реализация, недостающие импорты и API, ошибки SSL, запрет ослабленной проверки сертификатов, безопасный вывод, коды завершения и настоящий запуск выбранного интерпретатора. Отдельный сценарий запрещает сетевые и процессные вызовы и проверяет отсутствие TLS key log.

Фактический локальный результат от 9 сентября 2026 года:

| Среда / сценарий | Результат |
|---|---|
| CPython 3.12.14, macOS | Диагностика: код `0`; 10 тестов прошли |
| CPython 3.9.6, macOS | Диагностика: ожидаемый код `1`, отказ по версии без traceback |
| CPython 3.11, 3.13, prerelease, Python 4, PyPy | Проверена логика выбора на подставных метаданных; это не запуск соответствующих интерпретаторов |
| Entware / Keenetic | Утилита на роутере не запускалась, Python не устанавливался; аппаратная проверка не выполнена |

Соответствие модулей пакетам, локальная проверка CA/HTTPS и метод расчёта места описаны в [исследовании Entware](entware-runtime.md). До первой установки ещё нужны актуальные допустимые сборки, конкретный расчёт операции, матрица модели/архитектуры/KeeneticOS и разрешённая проверка на оборудовании. Этот документ не заменяет перечисленные проверки.
