# Офлайн-аудит пакетов Entware

[audit_entware.py](../scripts/audit_entware.py) читает локальный индекс `Packages` и архивы IPK, проверяет их состав и печатает JSON-отчёт. Архивы не устанавливаются, не исполняются и не извлекаются на диск. Утилита не обращается к сети и не вызывает `opkg`.

## Запуск

Используйте CPython 3.12 или новее в пределах стабильных выпусков Python 3 на компьютере разработчика. Из корня репозитория:

```sh
python3 -I -S -B scripts/audit_entware.py /path/to/Packages /path/to/ipk-directory
```

Первый аргумент — файл индекса, второй — каталог с IPK. Нужны архивы всех выбранных пакетов и их зависимостей из одного снимка каталога. Отсутствующий архив или несовпадение размера/хеша дают отказ, а не попытку скачать замену.

## Выбор пакетов

Начальный набор задан в `ROOT_PACKAGES`:

| Пакет | Проверяемая часть набора |
|---|---|
| `python3-light` | Модули стандартной библиотеки |
| `python3-codecs` | Кодеки |
| `python3-logging` | Логирование |
| `python3-openssl` | Криптографические расширения |
| `python3-urllib` | Модули URL/HTTP |
| `python3-uuid` | UUID |
| `ca-bundle` | PEM-набор сертификатов CA |

Зависимости собираются из `Depends` без повторного учёта общих пакетов. Виртуальная зависимость `ca-certs` явно разрешается через `ca-bundle`, с проверкой поля `Provides`. Поддерживаются простые имена зависимостей; ограничения версий и альтернативы не упрощаются молча, а отклоняются.

Этот набор определяет поведение аудитора, а не команду установки. Скрипт принимает архитектуры IPK `aarch64-3.10` и `all`; другие значения отклоняются. Он не определяет архитектуру компьютера или подключённого роутера.

## Что проверяется

1. Корректность записей индекса, отсутствие повторных пакетов/полей и наличие зависимостей.
2. Совпадение версий выбранных пакетов Python и соответствие общему правилу из [check_python.py](../scripts/check_python.py): стабильный Python 3 не ниже 3.12. Поддержан формат `X.Y.Z` или `X.Y.Z-R` с числовой ревизией; prerelease и неизвестный формат отклоняются до чтения IPK.
3. Допустимость имени IPK, совпадение `Size` и `SHA256sum` с индексом, чтение gzip/tar-оболочки с `data.tar.gz`.
4. Отсутствие абсолютных путей, компонентов `..`, повторных обычных файлов и неподдерживаемых типов записей. Ссылки из архива не разыменовываются, файлы остаются в памяти.
5. Наличие файлов модулей из общего списка `REQUIRED_MODULES`; для встроенных `errno` и `time` также допускаются символы инициализации в libpython. Отдельно проверяются файлы `_ssl`, `_hashlib`, `_uuid`.
6. Загрузка `opt/etc/ssl/certs/ca-certificates.crt` из `ca-bundle` в локальный TLS-контекст с проверкой имени и сертификата. Хранилище должно содержать CA; системное доверие не используется как fallback.

Ограничения чтения: индекс — 16 MiB, отдельный IPK — 64 MiB, распакованная tar-оболочка и tar-содержимое — по 128 MiB. Они не являются гарантией общего потребления памяти. Это ограниченный анализатор формата, не универсальная замена решателю пакетов.

## JSON-отчёт

| Поле | Содержимое |
|---|---|
| `index_sha256` | Хеш переданного индекса |
| `roots` | Начальный набор пакетов |
| `packages` | Версии, SHA-256, размеры и число записей каждого пакета |
| `totals` | Суммы размеров и числа записей выбранных пакетов |
| `module_owners` | Пакеты, в которых найдены признаки каждого обязательного модуля |
| `ca_count_local` | Число CA, загруженных в локальную OpenSSL |
| `limitations` | Границы статической проверки |

Размеры в `packages` и `totals` различаются:

- `download_bytes` — размер IPK из индекса, сверенный с файлом.
- `installed_size_field` — числовое значение `Installed-Size` без преобразования единиц; его семантика зависит от каталога.
- `payload_tar_bytes` — длина распакованного `data.tar`.
- `regular_file_bytes` — сумма размеров обычных файлов.
- `estimated_4k_bytes` — оценка с округлением обычных файлов до блоков 4 KiB и учётом остальных записей по 4 KiB.
- `archive_members` — количество записей в архивах, не число новых inode на накопителе.

Оценка блоков не измеряет реальную файловую систему. Утилита не вычисляет свободное место, дополнительное место при установке или объём резервной копии.

## Коды завершения и ограничения

| Код | Значение |
|---|---|
| `0` | Статический аудит завершён; отчёт выведен в stdout |
| `1` | Ошибка входных данных или проверки; в stderr выведено общее сообщение |
| `2` | Передано не два аргумента |

При ошибке исходные исключения, traceback и переданные пути не печатаются. Успешный отчёт не подтверждает подлинность недоверенного индекса: совпадение SHA-256 связывает архив только с переданными метаданными.

Наличие имени файла или символа не доказывает исполнение модуля, совместимость ABI и исправность установленного Entware. Загрузка PEM не проверяет HTTPS, актуальность всего набора доверия или сертификат VPN-сервера. Работа роутера, DNS, VPN и маршрутизация не проверяются.

## Тесты

```sh
python3 -I -S -B -m unittest discover -s tests -p test_audit_entware.py -v
```

IPK создаются искусственно в памяти и временных каталогах. [ca-test.crt](../tests/fixtures/ca-test.crt) — искусственный открытый CA; его закрытый ключ в репозитории отсутствует. Сеть, скачанные пакеты и роутер не требуются.
