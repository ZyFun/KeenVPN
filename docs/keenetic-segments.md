# Режимы устройств одного сегмента

`keenvpn.domain.keenetic_segment` рассчитывает режим выбранного сегмента и изменения явно выбранных записей в памяти. Он использует [записи устройств](keenetic-devices.md) и [текущий список политик](keenetic-policies.md). Функция не обращается к роутеру, не записывает RCI и не проверяет сетевой маршрут.

## Входные данные

`KeeneticSegment(segment_id, devices, policy_id=None)` содержит технический ID одного сегмента, `KeeneticDeviceInventory` его записей и исходную политику сегмента. `policy_id=None` означает отсутствие подтверждённого исходного ID, а не DIRECT. Заданный ID проверяется по формату и должен существовать в текущем списке политик при расчёте. Принадлежность записей должна быть заранее установлена доверенным вызывающим кодом. Модель не выводит её из имени, IP, производителя MAC или наблюдаемого интерфейса: интерфейс подключения не обязательно является ID сегмента. Offline-записи сохраняются. Записи с неизвестной принадлежностью нельзя произвольно включать в сегмент.

ID — строка от 1 до 128 символов: первый символ — латинская буква или цифра, остальные также допускают `_`, `.`, `:`, `/`, `-`. Модель не проверяет наличие такого сегмента на роутере. Она не является полным объектом настроек сегмента и не предназначена для замены RCI-объекта.

`SegmentSelection` содержит ID сегмента, `SegmentSelectionMode` и два кортежа ключей `DeviceIdentity`: `selected_devices` и `excluded_devices`. Смешение списков или повтор MAC, включая разный регистр, отклоняется. Пустой список допустим.

| Режим | Политика по умолчанию для сегмента | Явные изменения записей | Новые устройства без индивидуального назначения |
|---|---|---|---|
| `SELECTED_ONLY` (`selected_only`) | Переданная прямая политика | `selected_devices` получают явную VPN-политику | Прямой режим, пока устройство не выбрано |
| `WHOLE_SEGMENT` (`whole_segment`) | Переданная VPN-политика | Оба списка должны быть пустыми | VPN-режим сегмента |
| `EXCEPT_SELECTED` (`except_selected`) | Переданная VPN-политика | `excluded_devices` получают явную прямую политику | VPN-режим сегмента |

Индивидуальные назначения вне явного выбора сохраняются во всех режимах. Поэтому прежнее индивидуальное VPN-назначение сохраняется даже при `SELECTED_ONLY`, а прежнее прямое исключение — при `WHOLE_SEGMENT`. Смена режима сама по себе не сбрасывает эти настройки. Их число видно в `preserved_explicit_count`; возврат наследования выполняется отдельным явным изменением записи через `with_assignment()`.

Назначения вне явного выбора, отличающиеся от default, выделены в `conflicting_devices` и счётчике `conflicting_explicit_count`. Это индивидуальные исключения для просмотра, а не ошибка или запрет режима: например, невыбранная VPN-запись при `SELECTED_ONLY` или неперечисленная прямая запись при `EXCEPT_SELECTED`. Существующая политика третьей роли также выделяется, если отличается от default. Явно выбранные устройства/исключения в этот список не входят даже при повторе того же назначения. Неопределённые назначения учитываются только в `unresolved_device_count`.

`preview_segment_selection()` принимает сегмент, выбор, `KeeneticPolicySet`, `vpn_policy_id` и `direct_policy_id`. ID сегмента в выборе должен совпасть с ID переданного состава. Оба ID политик обязательны, различны и должны присутствовать в текущем списке. Роль политик устанавливает вызывающий код: само наличие ID не проверяет разрешённые WAN-подключения или работу перехвата. Имена и номера политик не зашиты.

## Результат расчёта

`SegmentSelectionPreview` содержит:

- `before` и `after` — исходный и рассчитанный состав и политика одного сегмента;
- `selection` — выполненный выбор;
- `default_policy_id` — предполагаемую политику по умолчанию сегмента;
- `before_default_policy_id` — исходный ID из `before.policy_id`;
- `default_changed` — `True`, если известная исходная политика меняется, `False`, если сохраняется, и `None`, если исходный ID неизвестен;
- `policy_ids` — ID из переданного списка политик;
- `changed_devices` — ключи реально изменённых записей в порядке исходного состава;
- `conflicting_devices` — ключи известных индивидуальных отклонений от default вне явного выбора, в порядке исходного состава;
- `new_device_mode` — `direct` или `vpn`, предполагаемое поведение нового устройства без индивидуального назначения.

`after.policy_id` содержит целевую политику. Изменение default видно отдельно от изменений записей: даже при пустом `changed_devices` политика сегмента может измениться. `default_changed=None` нельзя представлять как отсутствие изменений; сначала необходимо выяснить исходное состояние.

Результат хранит `vpn_policy_id` и `direct_policy_id`: оба ID должны существовать в `policy_ids` и различаться. Политика default должна соответствовать режиму, а каждая явно выбранная запись — иметь явное назначение нужной роли (VPN для выбранных устройств, DIRECT для исключений). Неизменённая запись допустима, только если уже имеет нужное назначение. Отсутствие назначения, наследование, read-only-состояние или третья политика у явно выбранной записи отклоняются. Эти проверки относятся к заявленным ролям; их реальное сетевое действие не проверяется.

Конструктор результата проверяет типы, совпадение ID сегмента, порядок и уникальность MAC до/после, список политик и согласованность default. `changed_devices` должен точно соответствовать изменённым записям в исходном порядке; изменённые записи должны входить в явный выбор. Выбранные MAC должны присутствовать в составе. Несогласованный результат отклоняется с `invalid_segment_preview` до вызова диагностики. Проверка модели не заменяет проверку фактического состояния роутера.

Выбор MAC вне состава сегмента даёт ошибку. Любой повтор MAC в составе блокирует расчёт: активная запись не получает преимущества. Выбор read-only-записи также блокирует расчёт, без частичного результата и изменения входа. Для изменений используется `KeeneticDevice.with_assignment()`: меняются только `policy/conform`, сохраняются deny, имя, IP, расписания, приоритеты, неизвестные поля и `details`. Повтор того же назначения не меняет даже исходную форму полей.

`policy_for(mac)` предварительно определяет политику известной записи после расчёта:

- явное назначение возвращает его ID, если он есть в переданном списке;
- подтверждённое наследование (`conform`) возвращает `default_policy_id`;
- отсутствие назначения, read-only-состояние или исчезнувшая индивидуальная политика возвращают `None`.

`None` означает неопределённость, а не прямой доступ. Пустой `policy` не считается наследованием. Существующая запись без назначения не переводится в наследование автоматически, даже если режим предполагает VPN для новых устройств. Неизвестный MAC в `policy_for()` даёт `device_missing`: его нельзя считать новым устройством только из-за отсутствия в переданном составе.

Рассчитанный ID не означает разрешение доступа: `access deny` сохраняется и учитывается отдельно. `new_device_mode` описывает намерение режима; фактические регистрация, наследование, запреты и маршрут на роутере этим расчётом не проверены. Результат не содержит ревизии внешнего источника и не является готовым черновиком применения.

## Пример

Все значения искусственные. Состав сегмента передаётся явно.

```python
from keenvpn.domain.keenetic_device import DeviceIdentity, KeeneticDevice, KeeneticDeviceInventory
from keenvpn.domain.keenetic_policy import KeeneticPolicy, KeeneticPolicySet, resolve_policy
from keenvpn.domain.keenetic_segment import (
    KeeneticSegment, SegmentSelection, SegmentSelectionMode, preview_segment_selection,
)

policies = KeeneticPolicySet((
    KeeneticPolicy("Policy17", "fixture-vpn"),
    KeeneticPolicy("Policy42", "fixture-direct"),
))
first = KeeneticDevice({"mac": "02:00:00:00:00:01", "conform": True, "access": "deny"})
second = KeeneticDevice({"mac": "02:00:00:00:00:02", "conform": True})
segment = KeeneticSegment("Bridge7", KeeneticDeviceInventory((first, second)), policy_id="Policy42")
selection = SegmentSelection(
    "Bridge7", SegmentSelectionMode.EXCEPT_SELECTED,
    excluded_devices=(DeviceIdentity("02:00:00:00:00:01"),),
)
result = preview_segment_selection(
    segment, selection, policies=policies,
    vpn_policy_id=resolve_policy(policies, "fixture-vpn").policy_id,
    direct_policy_id=resolve_policy(policies, "fixture-direct").policy_id,
)
assert result.policy_for("02:00:00:00:00:01") == "Policy42"
assert result.policy_for("02:00:00:00:00:02") == "Policy17"
assert result.new_device_mode == "vpn"
assert result.default_changed is True
assert result.before_default_policy_id == "Policy42"
assert result.after.policy_id == "Policy17"
assert result.after.devices.select("02:00:00:00:00:01").to_diagnostic()["access_denied"]
assert first.export()["settings"]["conform"] is True
```

## Безопасный вывод и ошибки

`repr()` моделей скрывает ID сегмента, MAC и политики. `to_diagnostic()` результата возвращает режим, поведение новых устройств, признак `default_changed` и счётчики: `record_count`, `changed_device_count`, `preserved_explicit_count`, `unresolved_device_count`, `access_denied_count`. `preserved_explicit_count` включает все индивидуальные назначения, оставшиеся без изменения, в том числе повторно выбранные с той же политикой. `unresolved_device_count` считает известные записи, для которых `policy_for()` вернул `None`.

`conflicting_explicit_count` показывает число индивидуальных отклонений вне явного выбора и не вычитается из общего `preserved_explicit_count`. Список `conflicting_devices` содержит приватные ключи MAC и не входит в безопасный вывод.

Остальные поля результата, `export()`, `dataclasses.asdict()` и локальные переменные traceback могут содержать приватные данные; они не подходят для журналов. `KeeneticSegmentError` содержит машинный `code`, фиксированный текст и отсоединённую цепочку исключений.

| Код | Причина |
|---|---|
| `invalid_segment` | Некорректная модель, ID или состав сегмента |
| `invalid_segment_selection` | Некорректный режим, тип списка/ключа, повтор MAC или список не для выбранного режима |
| `segment_scope_mismatch` | Выбор и состав относятся к разным сегментам |
| `segment_device_ambiguous` | В составе сегмента повторяется MAC |
| `invalid_segment_policies` | Некорректный текущий список политик |
| `invalid_segment_policy_target` | Отсутствует одна из двух политик, некорректен ID или обе роли указывают на один ID |
| `segment_policy_missing` | Заданный исходный ID политики сегмента отсутствует в текущем списке |
| `invalid_segment_preview` | Несогласованные типы, сегменты, политики, состав или список изменений при создании результата |

Проверка состава, ключа MAC, поиск записи и смена назначения также могут возвращать существующие `KeeneticDeviceError`: `invalid_device_inventory`, `invalid_device_mac`, `device_missing`, `device_read_only` и другие [ошибки модели устройства](keenetic-devices.md#безопасный-вывод-и-ошибки). Исходные значения в текст ошибки не включаются.
