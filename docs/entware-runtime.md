# Entware: пакеты Python, TLS и свободное место

Статус на 10 сентября 2026 года: исследованы официальный каталог `aarch64-k3.10` и содержимое IPK, выполнены локальные проверки на Mac. **Это кандидат набора зависимостей, не разрешение на установку и не подтверждённая совместимость с роутером.** Меню и bootstrap здесь не реализованы.

Минимальная ветка языка остаётся [CPython 3.12](python-runtime.md). Проверка файлов сборки 3.13 не заменяет её настоящий запуск в Entware. Матрица модели, архитектуры и KeeneticOS проверяется отдельно.

## 1. Проверенный состав каталога

Источники: официальный [индекс Packages](https://bin.entware.net/aarch64-k3.10/Packages) и [каталог пакетов](https://bin.entware.net/aarch64-k3.10/Packages.html). Индекс получен по HTTPS с проверкой сертификата. SHA-256 исследованной копии:

```text
0881742f1aaccd1c493428be70a3ed93186d5a3bfe6cabd30b94717e1683071e
```

Для каждого из 20 IPK сверены `Size` и `SHA256sum`, прочитано содержимое `data.tar.gz`. Архивы не установлены, `.pyc`, ELF и служебные скрипты не исполнялись. Совпадение хеша подтверждает соответствие этому индексу, но не независимую подпись издателя и не отсутствие уязвимостей.

### Явно выбираемые пакеты для новой среды

| Пакет | Наблюдаемая версия | Зачем нужен |
|---|---|---|
| `python3-light` | `3.13.9-2` | Основная библиотека, POSIX-модули, JSON, tar/gzip, Python-обёртки `ssl` и `hashlib` |
| `python3-codecs` | `3.13.9-2` | В частности, бинарный `unicodedata`, необходимый для Unicode/IDNA |
| `python3-logging` | `3.13.9-2` | Пакет `logging` |
| `python3-openssl` | `3.13.9-2` | Бинарные расширения `_ssl` и `_hashlib`, зависимость от OpenSSL и CA |
| `python3-urllib` | `3.13.9-2` | `urllib.parse`, `urllib.request`, `urllib.error`; подтягивает `python3-email` |
| `python3-uuid` | `3.13.9-2` | `uuid` и `_uuid`, зависимость от `libuuid` |
| `ca-bundle` | `20250419-2` | Явно выбранный PEM-набор доверенных CA |

Это список для проектирования bootstrap, **не команда `opkg install` для действующего роутера**. Номер версии — наблюдение каталога, не рекомендация закрепить старое исправление навсегда. До установки нужен отдельный выбор актуальных безопасных сборок, проверка ABI и работающей среды.

### Транзитивные зависимости

Ещё 13 пакетов; общие зависимости учитываются один раз:

| Пакеты | Наблюдаемая версия |
|---|---|
| `python3-base`, `libpython3`, `python3-email` | `3.13.9-2` |
| `libc`, `librt`, `libpthread` | `2.27-12` |
| `libgcc`, `libssp`, `libatomic` | `8.4.0-12` |
| `libbz2` | `1.0.8-2` |
| `zlib` | `1.3.1-1` |
| `libopenssl` | `3.5.5-1` |
| `libuuid` | `2.41.3-1` |

Наличие `libbz2` в зависимостях `python3-light` не делает `bz2` прямым требованием к коду KeenVPN. `python3-base` поставляет интерпретатор и, в частности, `io`, `os`, `stat`, `encodings.idna`. Для встроенных `errno` и `time` найдены символы инициализации в `libpython3`. Для остальных обязательных модулей найдены `.pyc`/`.so`; это статические признаки, **не проверка загрузчика, импорта и транзитивных импортов при исполнении**.

Не требуется устанавливать полный метапакет `python3`, `pip`, `openssl-util` или сторонние Python-библиотеки только ради этих проверок. Метапакет `python3` включает много дополнительных модулей. `unittest` нужен разработчику для тестов; в минимальный набор для роутера он не добавляется автоматически.

### Уже установленный Entware

- Сначала прочитать установленные версии, выбранный feed, архитектуры, зависимости и существующее доверие CA. Не выводить целиком конфиги с возможными приватными URL/учётными данными.
- Если установленное окружение удовлетворяет требованиям, сохранить его. Не переустанавливать Python только из-за отличия от снимка каталога.
- Имена пакетов не доказывают исправность среды. После разрешённой подготовки необходим настоящий запуск `check_python.py` в Entware, затем проверка CA/HTTPS.
- Python и его разделённые модули должны образовывать согласованную сборку. Не смешивать ветки 3.12/3.13 и несовместимые ABI, не подменять системный Python вне `/opt`.
- Добавление пакета может затронуть общие библиотеки других приложений. Если решатель предлагает их обновить, показать полный набор изменений и остановиться до отдельного согласования и подготовки восстановления. Безусловный `opkg upgrade` запрещён.

## 2. SSL, сертификаты и HTTPS — разные проверки

`ssl.pyc` находится в `python3-light`, но `_ssl.so` — в `python3-openssl`. Поэтому проверка одного имени пакета или файла недостаточна. После установки нужно проверить настоящий импорт и версию используемой OpenSSL, затем доверие и соединение.

В исследованном каталоге `python3-openssl` зависит от **виртуального `ca-certs`**. Его предоставляют как `ca-bundle`, так и `ca-certificates`. Само удовлетворение зависимости ещё не определяет формат хранилища:

| Пакет | Найденное содержимое |
|---|---|
| `ca-bundle` | `/opt/etc/ssl/certs/ca-certificates.crt`; ссылка `/opt/etc/ssl/cert.pem` |
| `ca-certificates` | Отдельные PEM-сертификаты и хешированные ссылки в `/opt/etc/ssl/certs`; общего файла bundle в этом пакете нет |

Для **кандидата новой среды** выбран `ca-bundle`: явная загрузка конкретного PEM позволяет отличить его от доверия Mac или другого системного хранилища. Для существующей среды нельзя автоматически удалять `ca-certificates`, заменять пользовательские CA, переписывать ссылки или глобальные переменные SSL. Хешированный каталог может работать через `capath`; сертификаты из него загружаются лениво, поэтому нулевой счётчик сразу после загрузки каталога сам по себе не доказывает ошибку. Нужна отдельная проверка его фактического использования. [Python SSL](https://docs.python.org/3.12/library/ssl.html#ssl.SSLContext.load_verify_locations).

Порядок проверки для будущего адаптера:

1. Проверить чтение выбранного хранилища, корректность формата и времени системы.
2. Создать TLS-контекст с `CERT_REQUIRED` и проверкой имени. Для нашего PEM-аудита используется `SSLContext(PROTOCOL_TLS_CLIENT)` и `load_verify_locations(cadata=...)`, без загрузки системного доверия.
3. Отдельно выполнить HTTPS-запрос к согласованному официальному адресу с таймаутом, проверкой цепочки, имени и HTTP-результата. Ошибки сети, TLS и HTTP различать; не переходить на HTTP, `CERT_NONE` или другой CA молча.
4. Отдельно проверить отказ при недоверенном сертификате/имени. Доступность сайта через прямой маршрут не доказывает работу VPN.

Обычный `create_default_context()` может обработать `SSLKEYLOGFILE`, поэтому офлайн-аудит его не использует. Реальный сетевой адаптер позже должен явно определить безопасную политику TLS, доверия, перенаправлений, прокси-окружения и журналирования. Аудит не реализует этот адаптер. [Создание TLS-контекста](https://docs.python.org/3.12/library/ssl.html#ssl.create_default_context), [urllib.request](https://docs.python.org/3.13/library/urllib.request.html).

### Фактические результаты на Mac

Использованы CPython 3.12.14 и CA из проверенного IPK, без установки Python 3.13 или Entware:

| Проверка | Результат |
|---|---|
| Явная загрузка PEM Entware без системного CA | 150 CA, проверка имени и сертификата включена |
| HTTPS `HEAD` к официальному индексу Entware, IPv4 | HTTP 200, TLS 1.2 |
| Тот же сервер с пустым хранилищем доверия | `SSLCertVerificationError`, ожидаемый отказ |
| Заведомо неверный SNI | Обрыв handshake; **не засчитан** как доказательство проверки имени клиентом |
| Пустой/повреждённый PEM, ослабленная проверка TLS | Отрицательные локальные тесты |
| Entware OpenSSL/CA/HTTPS на Keenetic | Не проверены |

Эта проверка не определяет маршрут Mac, DNS/Pritunl или состояние VPN. Загрузка CA подтверждает читаемость выбранного PEM, но не актуальность всего набора доверия и не аудит уязвимостей Python/OpenSSL.

## 3. Требования к свободному месту

Не использовать размер загрузки как требование к свободному месту. Для 20 пакетов, **без вычета уже установленного**, получено:

| Величина | Байт | Примерно MiB |
|---|---:|---:|
| Суммарный `Size` — скачиваемые IPK | 11 403 523 | 10,88 |
| Суммарный `Installed-Size` из индекса | 28 651 520 | 27,32 |
| Измеренные распакованные `data.tar` | 28 651 520 | 27,32 |
| Сумма размеров обычных файлов | 28 071 995 | 26,77 |
| Расчёт с округлением файлов до 4 KiB и запасом на записи каталогов/ссылок | 29 581 312 | 28,21 |

Здесь `Installed-Size` совпал с длиной распакованного tar и выражен в байтах, **не KiB**. Это не измерение занятого места EXT4. Оценка 4 KiB считает записи разных архивов повторно и не моделирует все метаданные файловой системы. В архивах 622 записи; это ориентир для расчёта inode, не количество новых inode на уже подготовленном USB.

### Расчёт пикового дополнительного места

Для каждого фактического файлового раздела отдельно, в байтах:

```text
требуется = загрузки + распаковка + новые файлы + резервная копия
          + служебные данные операции + свободный резерв
```

- **Загрузки:** новые IPK и архивы релиза, которые будут храниться одновременно. Подтверждённые уже скачанные файлы не считать повторно.
- **Распаковка:** максимальное одновременно существующее временное содержимое. Если последовательность этапов ещё не определена, считать все распаковки, не предполагать потоковую установку.
- **Новые файлы:** полные новые версии, а не разницу размеров новой и старой. Старые файлы не освобождают место до проверенного завершения.
- **Копия:** измеренный объём всех затрагиваемых файлов, метаданных и материалов восстановления. Не предполагать заранее коэффициент сжатия.
- **Служебные данные:** индекс/база opkg, журнал, списки файлов, возможные `.pyc`, временные записи и метаданные файловой системы. Неизвестное значение не подменять нулём.
- **Резерв:** отдельный запас для работающей системы и роста данных. Это выбранная политика операции, не число из репозитория Entware.

Условный пример только для Python: все 20 пакетов, загрузка/распаковка/новые файлы на одном разделе, без учёта служебных данных и будущего менеджера. Получается **66,41 MiB**; с условным резервом 16 MiB — **82,41 MiB**; с дополнительной копией размером с новые файлы — **110,62 MiB**. Числа 16/82/111/128 MiB не являются универсальным разрешением на установку. Для Xray, XKeen, GeoIP, конфигов и менеджера расчёт выполняется по выбранным артефактам отдельно.

### Условия будущей предварительной проверки

1. Убедиться, что `/opt` относится к нужному смонтированному USB и не стал каталогом внутренней памяти. Проверить устройство, тип и флаги монтирования, включая режим только чтения.
2. Для `/opt`, каталога загрузок, распаковки и копий определить реальные файловые системы. Объединять расходы на одном разделе; не суммировать свободное место разных разделов. `/tmp` может быть RAM, а не USB.
3. Получить доступные байты через `statvfs`: `f_bavail × f_frsize`, и доступные inode. Не считать зарезервированные блоки из `f_bfree` доступным запасом. Отсутствие достоверных данных требует остановки, а не положительного ответа. [os.statvfs](https://docs.python.org/3.12/library/os.html#os.statvfs).
4. Сравнить с полным пиком операции, повторить проверку перед изменениями и обрабатывать `ENOSPC`/ошибки записи даже после успешного расчёта. Проверка свободного места не резервирует его от других процессов.
5. Если места мало, предложить ручное освобождение/перенос согласованных каталогов. Не удалять копии, не форматировать USB и не выбирать `/tmp` скрытно.

Достаточное место не доказывает запись, `fsync`, атомарность или восстановление на USB. Эти проверки выполняются на оборудовании отдельно с разрешением. Обновление Python через opkg не является атомарным откатом нескольких пакетов: нужна проверенная процедура восстановления совместимых пакетов и доступа по SSH. Копии одних JSON-конфигов недостаточно; старые IPK могут исчезнуть из живого каталога.

## 4. Как повторить аудит без роутера

Утилита [audit_entware.py](../scripts/audit_entware.py) запускается **на компьютере разработчика** с CPython 3.12+ и стандартной библиотекой. Она читает подготовленные локальные файлы и печатает JSON, не скачивает пакеты, не вызывает opkg, не запускает содержимое архивов и не извлекает файлы на диск.

1. Скачать официальный `Packages` по проверенному HTTPS. Сохранить SHA-256; другой индекс означает новое исследование, а не воспроизведение снимка.
2. По `Filename` получить IPK семи выбранных пакетов и всех 13 зависимостей из того же каталога. Хранить их вне репозитория. Выбор поставщика `ca-certs` в этом аудите задан явно как `ca-bundle`.
3. Передать локальный индекс и каталог IPK:

```sh
python3 -I -S -B scripts/audit_entware.py /path/to/Packages /path/to/ipk-directory
```

Утилита берёт список модулей из `check_python.py`, а не поддерживает его отдельную копию. Сверяет хеши и размеры, собирает зависимости без повторов, ищет файлы/встроенные символы обязательных модулей и бинарных расширений, загружает CA в локальную OpenSSL, вычисляет размеры. Она не вычисляет свободное место на роутере и не разрешает установку по суммам отчёта. Большие архивы ограничены; это не универсальный анализатор произвольных недоверенных IPK и не замена решателя opkg.

Поддерживается только наблюдавшаяся простая запись `Depends`; неизвестные альтернативы/ограничения версии, отсутствующий поставщик, разные сборки разделённых пакетов Python, другая архитектура, неполный архив, несовпадение хеша и ошибка CA дают отказ. Индекс и IPK из разных снимков не смешивать. Код `0` означает завершённый **статический аудит**, `1` — ошибку, `2` — неправильное число аргументов. Исходные исключения и переданные пути не печатаются.

Локальные тесты:

```sh
python3 -I -S -B -m unittest discover -s tests -p test_audit_entware.py -v
python3 -I -S -B -m unittest discover -s tests -v
```

Фикстуры IPK создаются в памяти; `tests/fixtures/ca-test.crt` — искусственный открытый CA в формате PEM для теста загрузки. Его закрытый ключ не хранится в проекте; это не реальное доверие пользователя и не сертификат для установки на роутер. Тесты не требуют скачанных Entware-архивов, внешней сети или роутера.

## 5. Что остаётся до установки

- Проверить целевую платформу и состояние уже установленного Entware, согласованность ABI и общих библиотек.
- Согласовать актуальные версии и доверенный путь загрузки до появления Python: нельзя решать отсутствие SSL загрузкой установщика по HTTP без проверки подлинности.
- Рассчитать конкретную операцию с реальными файлами, местом, inode, служебным запасом и материалами восстановления.
- После отдельного разрешения проверить настоящий Python/CA/HTTPS на целевой системе; отдельно — нужные файловые операции и сценарии VPN.

На рабочем роутере в рамках этого исследования пакеты, файлы, службы, DNS, порт 53, Pritunl, автозапуск и маршрутизация не изменялись; аппаратная проверка не выполнялась.
