# Записи устройств Keenetic

`keenvpn.domain.keenetic_device` хранит записи устройств в памяти и возвращает новую модель при смене назначения политики. Ключ записи задаётся MAC, `presence` различает online/offline/unknown, а `KeeneticDeviceInventory` выбирает единственную запись по MAC. Модель не читает роутер, не записывает настройки и не подтверждает фактический маршрут клиента.

## Данные и сохранность

`KeeneticDevice(settings, details=...)` принимает:

- `settings` — полный словарь сохранённых настроек одного устройства с MAC в поле `mac`;
- `details` — необязательный словарь сопутствующих данных: имени и регистрации, закреплённого IP, наблюдаемых адресов, интерфейса и состояния. Вызывающий код отвечает за их сопоставление с записью.

Данные источников остаются разделёнными: назначение определяется только по `settings`, а наблюдаемая политика в `details` на него не влияет. Модель не объединяет записи в одно устройство по имени, IP или MAC и не вычисляет действующий маршрут по этим данным. Выбор по MAC возвращает только единственное совпадение; дубликаты не сливаются.

При создании модель делает независимый неизменяемый JSON-снимок. `export()` возвращает новую глубокую копию вида `{"settings": {...}, "details": {...}}`. Изменение исходного словаря или возвращённой копии не меняет модель. Сохраняются неизвестные вложенные поля, типы JSON-значений, порядок массивов и полей, пустые значения и отсутствие полей. Регистр MAC не нормализуется.

Поддерживаются обычные `dict` со строковыми ключами, `list`, `str`, `bool`, `int`, конечные `float` и `None`. Иные объекты, подклассы этих типов, циклы, вложенность свыше 64 уровней в снимке и значения, которые нельзя сериализовать, отклоняются с `invalid_device_data` без попытки преобразования в текст. MAC проверяется как шесть пар шестнадцатеричных цифр через двоеточие; проверка формата не доказывает наличие устройства.

## Идентичность и наблюдение

`device.identity` возвращает `DeviceIdentity`: ключ одной записи по MAC. Ключ сравнивается без учёта регистра; исходный MAC в `export()` остаётся прежним. Имя, IP, активность, политика и интерфейс не участвуют в равенстве ключей. Это ключ в рамках одного источника устройств, а не глобальный идентификатор физического аппарата.

Новый приватный MAC и MAC другого интерфейса остаются самостоятельными записями, даже если у них совпадают имя, IP или интерфейс роутера. Модель не определяет, является ли MAC приватным, когда он появился и принадлежат ли разные записи одному аппарату. Она не переносит между ними политику, регистрацию или запрет доступа. Старые offline-записи сохраняются.

Для чтения наблюдения используется `details["observation"]` — словарь с явным `mac`, совпадающим с `settings["mac"]` без учёта регистра. Свойство `presence` возвращает `DevicePresence`:

| Значение | Основание |
|---|---|
| `online` | В совпадающем наблюдении `active` равен булевому `true` |
| `offline` | В совпадающем наблюдении `active` равен булевому `false` |
| `unknown` | Нет совпадающего наблюдения либо отсутствует/не поддержан `active` |

Числа `0`/`1` и строки не считаются булевыми значениями. Отсутствие наблюдения не означает offline. Эти статусы относятся только к переданному снимку: свежесть данных, доступ в интернет и работа VPN ими не проверяются. `access: deny` не подменяет наблюдаемую активность.

`observed_interface_id` возвращает непустой строковый `observation.interface.id` либо `None`, также только при совпадающем MAC. Это приватный ID интерфейса **роутера**; из него не выводятся тип подключения клиента или принадлежность MAC физическому устройству. Смена наблюдаемого интерфейса при том же MAC не создаёт новый ключ. Неизвестные форматы и несовпадающие наблюдения остаются без изменений в `details`, но не используются для этих свойств.

## Выбор отдельной записи

`KeeneticDeviceInventory` принимает кортеж готовых `KeeneticDevice` одного источника. Он сохраняет все записи и их порядок, включая offline и дубликаты. Источники он не объединяет; за получение и сопоставление `settings`/`details` отвечает вызывающий код.

`select(mac)` возвращает единственную запись с указанным MAC без учёта регистра. Отсутствующий MAC даёт `device_missing`, повторяющийся — `device_ambiguous`, даже если только одна из записей online. Выбора первой записи, поиска по имени/IP и переноса настроек нет. Дубликаты доступны через `devices` для просмотра; выбор другого, уникального MAC остаётся допустимым. Некорректный MAC отклоняется до поиска.

```python
from keenvpn.domain.keenetic_device import (
    DevicePolicyMode, DevicePresence, KeeneticDevice, KeeneticDeviceInventory,
)

old = KeeneticDevice(
    {"mac": "02:00:00:00:00:01", "policy": "Policy17"},
    details={"observation": {
        "mac": "02:00:00:00:00:01", "name": "fixture-client", "active": False,
    }},
)
new = KeeneticDevice(
    {"mac": "02:00:00:00:00:02"},
    details={"observation": {
        "mac": "02:00:00:00:00:02", "name": "fixture-client", "active": True,
    }},
)
inventory = KeeneticDeviceInventory((old, new))
assert inventory.select("02:00:00:00:00:01") is old
assert old.presence is DevicePresence.OFFLINE
assert inventory.select("02:00:00:00:00:02") is new
assert new.assignment.mode is DevicePolicyMode.UNASSIGNED
assert old.identity != new.identity
```

## Назначение политики

`DevicePolicyAssignment` отделяет назначение от разрешения доступа:

| Режим | Значение сохранённых полей |
|---|---|
| `explicit` | Непустой допустимый `policy`, `conform` отсутствует либо равен `false` |
| `inherit` | `conform: true`, `policy` отсутствует либо пуст |
| `unassigned` | `policy` отсутствует либо пуст, `conform` отсутствует либо равен `false` |
| `unknown` | Противоречивое сочетание или неподдерживаемый формат `policy`/`conform` |

`unassigned` не означает DIRECT или наследование. `unknown` доступен для просмотра и экспорта, но не как цель изменения.

`with_assignment(assignment, policies=...)` меняет только пару `policy`/`conform`, возвращая новую модель. При явном назначении ID должен присутствовать в переданном `KeeneticPolicySet`; используйте [определение политики по текущему списку](keenetic-policies.md). Отсутствующий ID блокирует операцию, включая повтор прежнего назначения. Список проверяется заново при каждом вызове; эта проверка в памяти не подтверждает актуальность состояния роутера.

При смене режима исходные `policy`/`conform` удаляются, затем записывается только целевой `policy` либо `conform: true`. Для `unassigned` оба поля отсутствуют. Повтор того же назначения сохраняет исходную форму: например, пустой `policy` и явный `conform: false` не удаляются.

Все остальные поля сохраняются целиком: `access`, `deny`, `permit`, имя, IP, приоритет, расписания, регистрация, ограничение скорости и неизвестные параметры. `details` не меняется. Действие над `access: deny` или `deny: true` не разрешает доступ и не добавляет `permit`.

При неизвестном назначении, неподдерживаемом `access`, небулевых `deny`/`permit` или противоречии разрешающих и запрещающих признаков модель имеет `read_only = True`. Экспорт сохраняет исходные данные; смена назначения отклоняется с `device_read_only`.

Противоречием считаются также `access: deny` вместе с явным `deny: false` и `access: permit` вместе с `permit: false`. Отсутствующий флаг не равен явному `false`: запись с одним `access: deny` или `access: permit` остаётся редактируемой. Булев `false` без `access` сохраняется и сам по себе не блокирует изменение.

```python
from keenvpn.domain.keenetic_device import (
    DevicePolicyAssignment, DevicePolicyMode, KeeneticDevice,
)
from keenvpn.domain.keenetic_policy import KeeneticPolicy, KeeneticPolicySet, resolve_policy

policies = KeeneticPolicySet((KeeneticPolicy("Policy17", "fixture-vpn"),))
resolution = resolve_policy(policies, "fixture-vpn")
assert resolution.resolved

device = KeeneticDevice(
    {"mac": "02:00:00:00:00:01", "access": "deny", "deny": True, "priority": 6},
    details={"name": "fixture-device", "ip": "192.0.2.17"},
)
updated = device.with_assignment(
    DevicePolicyAssignment(DevicePolicyMode.EXPLICIT, resolution.policy_id),
    policies=policies,
)
assert updated.assignment.policy_id == "Policy17"
assert updated.export()["settings"]["access"] == "deny"
assert updated.export()["details"] == device.export()["details"]
assert "policy" not in device.export()["settings"]
```

Этот результат — локальная модель изменённой записи. Он не является запросом RCI, разрешением на применение или доказательством работоспособности VPN.

## Безопасный вывод и ошибки

`repr(device)` скрывает данные. `repr(assignment)` показывает только режим. `to_diagnostic()` возвращает `assignment`, `read_only`, `access_denied` и `observation_mismatch`, без MAC, имени, IP, policy ID и неизвестных значений. `access_denied` отмечает наличие сохранённого `access: deny` или `deny: true`; отсутствие признака не доказывает, что доступ разрешён.

`observation_mismatch` равен `true`, если в словаре `details.observation` явно указан строковый `mac`, отличающийся от MAC записи без учёта регистра. Это позволяет заметить ошибку сопоставления, сохранив `presence = unknown` и исходные данные для просмотра. Пустой или некорректный строковый MAC также даёт `true`; отсутствующий, нестроковый MAC или наблюдение неизвестного формата — `false`, поскольку сравнение невозможно. Значение `false` не подтверждает наличие или корректность наблюдения. Признак не меняет `read_only` и правила локальной смены назначения.

`repr(identity)` скрывает MAC, `repr(inventory)` показывает только число записей. `inventory.to_diagnostic()` возвращает счётчики `record_count`, `distinct_mac_count`, `online_count`, `offline_count`, `unknown_count`, `observation_mismatch_count`. Последний считает записи с несовпавшим MAC наблюдения; они также входят в `unknown_count`. Счётчики относятся к записям, а не физическим устройствам; дубликаты учитываются отдельно. `identity.mac`, `observed_interface_id` и записи `inventory.devices` предназначены для доверенного кода и не являются безопасным выводом.

`export()` предназначен для доверенного кода и раскрывает приватные данные. Это не представление для терминала или журнала. Снимок не зашифрован; `dataclasses.asdict()`, приватные поля и захват локальных переменных traceback также не являются безопасными отчётами.

`KeeneticDeviceError` содержит машинный `code` и фиксированный текст без исходных значений. Активное чужое исключение не сохраняется в его `__context__` или `__cause__`.

| Код | Причина |
|---|---|
| `invalid_device_data` | Неподдерживаемые или несериализуемые данные |
| `invalid_device_mac` | Нет MAC или его формат недопустим |
| `invalid_device_assignment` | Некорректная модель назначения или цель `unknown` |
| `device_read_only` | Неизвестные или противоречивые настройки назначения/доступа |
| `device_policy_missing` | Целевого ID нет в переданном списке политик |
| `invalid_device_policies` | Некорректный список политик |
| `invalid_device_inventory` | Передан не обычный кортеж `KeeneticDevice` или неподдерживаемый тип элемента |
| `device_missing` | В списке нет записи с выбранным MAC |
| `device_ambiguous` | Выбранному MAC соответствует несколько записей |
