# Диагностика Python

[check_python.py](../scripts/check_python.py) проверяет выбранный интерпретатор и печатает результат каждой проверки. Утилита ничего не устанавливает, не меняет конфигурацию и не выполняет сетевые запросы.

## Запуск и версия

Из корня репозитория:

```sh
python3 -I -S -B scripts/check_python.py
```

`-I` изолирует запуск от пользовательского Python-окружения, `-S` отключает обработку `site`, `-B` запрещает запись `.pyc`. Проверяется именно запущенный интерпретатор; автоматической подмены другим Python нет.

Положительный результат требует стабильного **CPython 3.12 или новее в пределах Python 3**. Python ниже 3.12, предварительные выпуски и другие реализации отклоняются. Синтаксис самого скрипта совместим с Python 3.9, чтобы показать отказ старой среды без ошибки разбора.

При неподходящей версии проверка останавливается до импорта перечисленных ниже модулей. Аргументы скрипт не принимает.

## Проверяемые модули

Полный список задан в `REQUIRED_MODULES`:

| Группа | Модули |
|---|---|
| Терминал и сообщения | `argparse`, `getpass`, `termios`, `logging` |
| Модели и контексты | `dataclasses`, `enum`, `typing`, `contextlib` |
| Форматы и адреса | `json`, `re`, `ipaddress`, `urllib.parse`, `base64`, `binascii` |
| Unicode и домены | `unicodedata`, `encodings.idna` |
| Файловые API | `pathlib`, `os`, `stat`, `shutil`, `tempfile`, `io` |
| Хеши и идентификаторы | `hashlib`, `hmac`, `secrets`, `uuid` |
| Блокировки, процессы и время | `fcntl`, `subprocess`, `signal`, `errno`, `time`, `datetime` |
| Лимиты процессов, ожидание и двоичные структуры | `resource`, `select`, `struct` |
| Сетевые API | `socket`, `ssl`, `urllib.request`, `urllib.error`, `http.client` |
| Архивы | `tarfile`, `gzip`, `zlib` |

Отсутствие транзитивной зависимости также считается ошибкой импорта. Список включает POSIX-модули `termios`, `fcntl` и `resource`; наличие обычной установки Python на Windows не означает прохождения проверки.

## Дополнительные проверки

- Наличие файловых API `replace`, `fsync`, `chmod`, `fchmod`, `open` и флагов `O_NOFOLLOW`, `O_DIRECTORY`.
- Поддержка `dir_fd` у `open`, `mkdir`, `rename`, `unlink` и `stat`, `listdir` по дескриптору каталога и `stat` без перехода по ссылке: на них опираются [хранилище метаданных менеджера](manager-metadata.md) и [хранилище сессии черновика](draft-session.md).
- Наличие `flock` и флагов блокировки, `subprocess.run` и `TimeoutExpired`.
- Создание клиентского TLS-контекста с проверкой имени и обязательной проверкой сертификата.
- Результат SHA-256, преобразование JSON с Unicode, IDNA-кодирование и сжатие/распаковка gzip в памяти.
- Наличие `tarfile.data_filter`.

Проверка API не выполняет файловые операции, блокировки или запуск процессов. TLS-контекст создаётся без загрузки CA и handshake; `SSLKEYLOGFILE` не обрабатывается. Утилита рассчитана на доверенный интерпретатор и его стандартную библиотеку, а не на безопасное исполнение посторонних модулей.

## Вывод и коды завершения

Каждая проверка выводится с `OK:` или `ОШИБКА:`. Исходные исключения, traceback и ошибочно переданные аргументы не печатаются.

| Код | Значение |
|---|---|
| `0` | Все выполненные проверки пройдены |
| `1` | Не подходит версия, отсутствует модуль/API или проверка завершилась ошибкой |
| `2` | Переданы аргументы |

**Код `0` не подтверждает** актуальность исправлений безопасности, наличие пакетов Entware, доверенные CA, HTTPS, файловые гарантии USB, совместимость роутера или работу VPN. Наличие API не равно проверке операции на файловой системе.

## Тесты

```sh
python3 -I -S -B -m unittest discover -s tests -p test_check_python.py -v
```

Тесты проверяют границы версий, ошибки импортов/API/TLS, безопасный вывод, коды завершения и запуск выбранного интерпретатора. Проверки подставных версий не являются запуском соответствующих интерпретаторов. Сеть и роутер не требуются.

Отдельная утилита [аудита Entware](entware-runtime.md) использует то же правило версии и тот же список модулей.

## Python для изолированного исполнителя Xray

[Изолированный исполнитель](draft-session.md#изолированный-linux-исполнитель)
дополнительно требует `ctypes` и его бинарное расширение `_ctypes`.
В Entware они поставляются отдельным пакетом `python3-ctypes`, который не входит
в базовый набор офлайн-аудитора. Базовая диагностика `check_python.py` не проверяет
`ctypes`: её код `0` не подтверждает готовность изолированного исполнителя.

Для выбранного интерпретатора Entware импорты и наличие API проверяются отдельно:

```sh
/opt/bin/python3 -I -S -B -c 'import ctypes, resource, select, struct; assert callable(ctypes.CDLL); assert callable(resource.prlimit); print("OK")'
```

Команда не устанавливает пакеты и не запускает Xray. Импорт `ctypes` также загружает
`_ctypes`; отсутствие дополнительного пакета остаётся препятствием для исполнителя.
Проверка импортов и наличия API не подтверждает полномочия, ABI и работу механизмов
изоляции: их проверяет сам исполнитель. При доступных зависимостях меню
подключает исполнитель к пункту 7 → 2. Для проверки сохранённого кандидата
этот пункт может создать временные приватные файлы и запустить отдельный
проверочный процесс. Просмотр схемы его не запускает.

## Python для резервной копии установки

[Команда резервного копирования](router-backup.md) дополнительно использует
`sqlite3` с API `Connection.backup`, `platform` и `syslog`. Они пока не входят
в базовый `REQUIRED_MODULES` этой диагностической утилиты: её код `0` сам по
себе не означает готовность к запуску бекапа. На Entware модуль SQLite
предоставляется пакетом `python3-sqlite3`; полный метапакет `python3` включает
его в зависимости. После согласованной установки проверяется реальный импорт:

```sh
/opt/bin/python3 -I -S -B -c 'import sqlite3, tarfile, gzip, hashlib, fcntl, platform, syslog; assert callable(sqlite3.Connection.backup); print("OK")'
```

Импорт не заменяет создание и проверку пробного архива на выбранном хранилище.
